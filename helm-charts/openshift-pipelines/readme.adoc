= OpenShift Serverless

This Helm chart deploys OpenShift Pipelines. OpenShift Pipelines is an open-source, Kubernetes-native framework for building Continuous Integration and Continuous Delivery (CI/CD) pipelines. It automates and standardizes application builds, tests, and deployments across Kubernetes environments.

== Installing the Chart

To install the chart:

[source,bash]
----
helm install --name openshift-pipelines helm-chart/openshift-pipelines
----

== Uninstalling the Chart

To uninstall/delete the chart deployment:

[source,bash]
----
helm delete openshift-pipelines
----

== Additional Notes on TektonConfig

=== Addon

- Enabling `pipelineTemplates` requires `resolverTasks` to be set to `true` because the templates reference standard cluster build tasks.
- The chart automatically set `resolverTasks` to `true` if `pipelineTemplates` is set to `true`.
- `resolverTasks` is a replacement for `clusterTasks`, which has been deprecated because of security risks, lack of built-in versioning, and management difficulties.
- `communityResolverTasks` is a replacement for `communityClusterTasks`, which has been deprecated because of security risks, lack of built-in versioning, and management difficulties.

[NOTE]
====
- Each goroutine pulls work items (`PipelineRun`/`TaskRun` reconciliations) from the pipeline controller's work queue.
- A higher `threads-per-controller` value results in more parallel reconciliation, improving throughput under load.
- More parallel reconciliation increases memory usage and could cause the controller pods to be OOMKilled when they are pushed to the limit.
====

=== Tekton Results

Tekton Results is a specialized service designed for long-term storage, grouping, and querying of execution data, decoupling historical record-keeping from the real-time Pipeline controller. It alleviates the performance overhead of storing CI/CD history in Kubernetes etcd by offloading completed `PipelineRun` and `TaskRun` data to a dedicated database backend.

The chart configures Tekton Results with an internal PostgreSQL database for persistent storage. It defaults to a 1Gi `PersistentVolumeClaim`, which is typically sufficient for basic environments and accommodates roughly 100,000 pipeline runs.

Data retention is managed by the Retention Policy Agent, which prunes old records according to configurable policies:

- Failed runs: Retained for the duration specified by `result.retention.failed` Helm value (default: 14 days).
- Fallback retention: Specified by `result.retention.default` Helm value (default: 7 days).
- Pruning: Handled by a CronJob scheduled at a random time between 12:00 AM and 7:00 AM.

=== Pruner and TektonPruner

The chart enables the event-driven **Tekton Pruner**, which uses a Kubernetes controller to automatically clean up completed `PipelineRun` and `TaskRun` resources based on configurable time-based (TTL) or history-based policies. The legacy CronJob-based **Pruner** is disabled, as both pruners cannot be enabled simultaneously.

The chart adds `tektonPruner.successfulHistoryLimit` and `tektonPruner.failedHistoryLimit` and use it to configure `historyLimit` which must be equal to or less than 100.
