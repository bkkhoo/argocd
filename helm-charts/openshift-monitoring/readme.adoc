= Configure OpenShift Monitoring

Configure the preinstalled OpenShift Monitoring stack.

== Installing the Chart

To install the chart:

[source,bash]
----
helm install --name openshift-monitoring helm-chart/openshift-monitoring
----

== Configuration

The following table lists the configurable parameters/values of this Helm chart and their default values.

[cols="2,1,4", options="header"]
|===
| Parameter
| Default
| Description

| enableUserWorkload
| true
| Enable/Disable user workload monitoring in OpenShift.

| storageClass
| None
| Assign specific storage class for OpenShift monitoring components' persistent volumes.

| platform.prometheusK8s.retention
| 7d (7 days)
| Define data retention time to prevent indefinite storage growth for the Prometheus instance responsible for monitoring core OpenShift platform component.

| platform.prometheusK8s.storage
| 20Gi
| Define specific storage resource requests for persistent volumes of the Prometheus instance responsible for monitoring core OpenShift platform component.

| platform.alertmanagerMain.storage
| 10Gi
| Define specific storage resource requests for persistent volumes of the default Alertmanager instance.

| userWorkload.prometheus.retention
| 24h (24 hours)
| Define data retention time to prevent indefinite storage growth for the Prometheus instance responsible for monitoring user workloads.

| userWorkload.prometheus.storage
| 10Gi
| Define specific storage resource requests for persistent volumes of the Prometheus instance responsible for monitoring user workloads.

| userWorkload.thanosRuler.retention
| 24h (24 hours)
| Define data retention time to prevent indefinite storage growth for the Thanos Ruler instance responsible for monitoring user workloads.

| userWorkload.thanosRuler.storage
| 10Gi
| Define specific storage resource requests for persistent volumes of the Thanos Ruler instance responsible for monitoring user workloads.
|===

== Interaction with RHACM Multi Cluster Observability

When Red Hat Advanced Cluster Management (RHACM) enables the observability service on OpenShift clusters, the observability endpoint operator automatically updates the OpenShift Monitoring ConfigMaps. The injected configuration causes the openshift-monitoring ArgoCD Application to become **OutOfSync**.

The following configurations are added to minimize **OutOfSync** state:

- link:./templates/platform-workload-configmap.yaml[platform workload ConfigMap] (`cluster-monitoring-config` in `openshift-monitoring` namespace):
  ** `alertmanagerMain.volumeClaimTemplate.metadata`
  ** `alertmanagerMain.volumeClaimTemplate.status`
  ** `nodeExporter`
  ** `prometheusK8s.volumeClaimTemplate.metadata`
  ** `prometheusK8s.volumeClaimTemplate.status`
- link:./templates/user-workload-configmap.yaml[user workload ConfigMap] (`user-workload-monitoring-config` in `openshift-user-workload-monitoring` namespace):
  ** `prometheus.volumeClaimTemplate.metadata`
  ** `prometheus.volumeClaimTemplate.status`
  ** `thanosRuler.volumeClaimTemplate.metadata`
  ** `thanosRuler.volumeClaimTemplate.status`

There is no easy way to work around the **OutOfSync** issue, as some of the injected configurations are dynamic, e.g.:

- link:./templates/platform-workload-configmap.yaml[platform workload ConfigMap] (`cluster-monitoring-config` in `openshift-monitoring` namespace):
  ** `prometheusK8s.additionalAlertmanagerConfigs`
  ** `prometheusK8s.externalLabels`
- link:./templates/user-workload-configmap.yaml[user workload ConfigMap] (`user-workload-monitoring-config` in `openshift-user-workload-monitoring` namespace):
  ** `prometheus.additionalAlertmanagerConfigs`
